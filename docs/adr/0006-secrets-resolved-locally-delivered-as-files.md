# Secrets resolved locally, delivered as files

Secrets are resolved on the operator's machine at deploy time (op, bw, bws, any command) and written to the Server as versioned files, mounted into containers via compose `secrets:` with the `*_FILE` convention. Files are 0444 inside 0700 directories owned by the deploy user: the directory protects them on the host, and any container user can read its own mount, because compose ignores `uid/gid/mode` without Swarm; `env_file` is a fallback. Files keep values out of `docker inspect` and out of compose `${VAR}` interpolation, which leaks via `docker compose config`. Server-side jobs read stored files instead of calling a password manager, because 1Password service-account read caps are shared account-wide and a crash loop can lock every account for a day. Each Service receives only the secrets it declares, unlike Coolify which injects all variables into every container.
