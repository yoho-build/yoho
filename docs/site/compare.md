# Compare Yoho

An honest comparison of **Yoho**, **Uncloud**, **Kamal**, **Coolify**, and **Dokploy**. Facts about external tools are **as of 2026-11** and linked to each project's own documentation.

## When to pick another tool

- **Need a cross-cloud, multi-machine WireGuard mesh today: use [Uncloud](https://github.com/psviderski/uncloud).** Uncloud ships a WireGuard mesh with peer discovery, NAT traversal, DNS service discovery, and cluster-shared Caddy TLS out of the box. Yoho's multi-Server Compose Roles ([#81](https://github.com/yoho-build/yoho/issues/81)) and opt-in WireGuard mesh ([#86](https://github.com/yoho-build/yoho/issues/86)) are planned, not shipped; today Yoho covers multiple Servers via Docker Swarm.
- **Want a Ruby-native, single-container-per-role workflow with multi-server roles today: use [Kamal](https://kamal-deploy.org).** Kamal is mature, Rails-aligned, and already supports multi-server roles without Swarm.
- **Want a browser-based self-hosted PaaS with Git-push deploys and a team web UI: use [Coolify](https://coolify.io/docs) or [Dokploy](https://docs.dokploy.com).** Both give you a hosted control plane on your server if you prefer clicking through a dashboard over a CLI.

## Where Yoho focuses

Yoho is built for operators who already keep their stack in `compose.yaml` and want:

1. **No control plane to patch or back up**, and a clean exit path: if you stop using Yoho, your containers, volumes, and compiled `compose.yaml` keep running under plain `docker compose`.
2. **Recovery you can test before an outage:** Stateful Services are pinned and never `down -v`, Backups run to restic/S3/B2/SFTP/rclone, and `yoho backup drill` restores into a throwaway project to verify your data and measure recovery time ([Losing a Server](backups.md#losing-a-server)).
3. **File-delivered secrets and database password rotation:** secrets stay out of `docker inspect` by default, and `yoho secrets rotate --generated` rotates generated Postgres/MySQL/MariaDB credentials in place.
4. **Scoped team and CI access without a platform:** the [Gate](team-access.md) grants fixed verbs to one App Destination with an audit log, without giving Members SSH shells or Docker socket access.
