# v0.8.1

## Upgrade notes

- **Gate (`yoho access install`): yes, on Servers with a Gate, to keep the Proxy on one version.** The Gate binary has the default Proxy image compiled in, and `settings.json` leaves `proxy.image` empty unless the Yoho file sets it. Until the Gate is updated, a Member's deploy or rollback through a v0.8.0 Gate recreates `yoho-proxy` back on `basecamp/kamal-proxy:v0.10.2`, and the next operator deploy or rollback moves it forward again; each swap is a brief Proxy interruption for every App on the Server. Run `yoho access install -d DESTINATION` with this release, or pin `proxy.image` in the Yoho file and run `yoho access secrets push -d DESTINATION` for every gated Destination on the Server so both sides use the same image.
- **Gate settings (`yoho access secrets push`): no shape change.** `settings.json`, the pushed secrets and `members.yml` keep their shape. If you pin or change `proxy.image`, push the settings again for every gated Destination on the Server; the Gate uses only the pushed value.
- **Older Gate and new compose: no.** This release adds no compose or `x-yoho` keys.
- **Running containers: only `yoho-proxy`.** Upgrading the CLI or the Gate touches no container. App Services are not recreated because of this release.
- **Proxy: yes, the default image moves from `basecamp/kamal-proxy:v0.10.2` to `basecamp/kamal-proxy:v0.10.3`.** `yoho plan` shows `proxy yoho-proxy: upgrade v0.10.2 -> v0.10.3`, and the next `yoho deploy`, `yoho rollback` or `yoho secrets rotate` (or `yoho proxy upgrade [-y]`, in a maintenance window) recreates `yoho-proxy` on each Server: connections to every App on the Server are refused for about a second, routes are kept. The Proxy is shared by every App on a Server, so upgrade the Yoho CLI for all Apps that deploy to that Server, or pin `proxy.image` to one tag in each of them. To stay on the old version, set `proxy.image: basecamp/kamal-proxy:v0.10.2` (and push the Gate settings, see above).

## Changes

- Pin kamal-proxy v0.10.3 (commit `d28ff16b1addfda26a2d822c2c0a624d39e6360f`). It rebuilds kamal-proxy with Go 1.27.4 and updated `golang.org/x/net`, `golang.org/x/crypto` and `quic-go`, fixing the govulncheck findings in the standard library (`net/http`, `crypto/x509`) and those modules. No flags or route rules change; the route conflict and on-demand TLS checks Yoho mirrors are the same as in v0.10.2.
- The reusable workflows `.github/workflows/deploy.yml` and `.github/workflows/yoho-preview.yml` pin `setup-yoho` to v0.8.1.
