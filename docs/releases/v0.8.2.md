# v0.8.2

## Upgrade notes

- **Gate (`yoho access install`): no.** The fixes are in operator commands: a Gate deploy or rollback runs no Proxy Hooks, so the Hook order does not apply to it. Updating the Gate is harmless.
- **Gate settings (`yoho access secrets push`): no.** `settings.json`, the pushed secrets and `members.yml` keep their shape.
- **Older Gate and new compose: no.** This release adds no compose or `x-yoho` keys.
- **Running containers: no restarts.** Upgrading the CLI or the Gate touches no container, and no Service is recreated because of this release.
- **Proxy: unchanged.** The default image stays `basecamp/kamal-proxy:v0.10.3` and its configuration is the same, so a Proxy already on v0.10.3 is not recreated.
- **`yoho-preview.yml` callers:** the reusable workflow now installs Yoho v0.8.2 by default instead of `latest`. Set `yoho-version: latest` to keep the old behavior.

## Changes

- A deploy, rollback or `yoho secrets rotate` that recreates the Proxy (for example for the v0.10.3 image in v0.8.1) now pulls the image before it runs the `pre-proxy-reboot` Hook. Before, a failed pull (registry outage, Docker Hub rate limit) left the Server drained from its load balancer with the old Proxy still running and no `post-proxy-reboot`. `yoho proxy boot` now pulls before its Hooks too; `yoho proxy upgrade` already did.
- `yoho proxy upgrade` on a Server whose `yoho-proxy` is stopped no longer fails with `unexpected new route` for every route. A stopped Proxy cannot list its routes, so the upgrade warns that routes cannot be compared and only checks that they load again, as it does for a Proxy older than v0.10.0.
- `yoho proxy status` shows every Server of the Destination, not only the first. For a stopped, restarting or missing Proxy it prints the container line and the version summary instead of failing on `docker exec`, and a failing Docker call is an error rather than `not running`.
- The reusable workflow `.github/workflows/yoho-preview.yml` defaults `yoho-version` to the release it belongs to (v0.8.2), like `deploy.yml`, so pinning the workflow also pins the CLI. Both workflows pin `setup-yoho` to v0.8.2.
